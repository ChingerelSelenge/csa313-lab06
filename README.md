# Лаборатори 6

Оюутны нэр: С. Чингэрэл
Оюутны код: B232270010

## Зорилго

Банкны шилжүүлгийн функцэд category-partition аргаар тестийн
сонголт, төлөөлөх утга болон хязгаарлалт тодорхойлно.
PICT ашиглан pairwise тестийн багц үүсгэж, гараар боловсруулсан
спецификацитай харьцуулна.

## Хэсэг A: Category-Partition гараар — Шилжүүлгийн функц 

Энэхүү лабораторийн ажилд банкны данс хооронд мөнгө шилжүүлэх `POST /transfer` үйлдлийг Category-Partition болон PICT аргаар тестлэх загвар боловсруулна.

Давхар алдааны үед шилжүүлэгч дансны оршин байх болон төлөвийг, дараа нь хүлээн авагчийг, эцэст нь дүн ба санхүүгийн хязгаарыг шалгах эрэмбэ сонгосон. Энэ нь эхлээд оролцогч дансуудыг баталгаажуулж, дараа нь шилжүүлгийн боломжийг үнэлэх логиктой.

## Даалгавар A1 — Сонголт ба төлөөлөх утгууд:

Банкны шилжүүлгийн POST /transfer үйлдлийн оролтыг From, To, Amount, Currency гэсэн дөрвөн параметрт ангилсан. Параметр бүрийн зөв болон алдаатай төлөвийг тодорхойлж, төлөөлөх тестийн өгөгдөл сонгосон.


| Сонголт | Ангилал / утга | Төлөөлөх өгөгдөл |
|---|---|---|
| `From` | `Valid` | Байгаа, царцаагдаагүй `ACC_FROM` |
| `From` | `Frozen` | Байгаа, царцаагдсан `ACC_FROM` |
| `From` | `Missing` | Үүсгээгүй `ABSENT_FROM` |
| `To` | `Valid` | Байгаа, from-оос өөр `ACC_TO` |
| `To` | `Missing` | Үүсгээгүй `ABSENT_TO` |
| `To` | `SameAsFrom` | `to` нь `from`-той ижил |
| `Amount` | `Normal` | Хөрвүүлсний дараа үлдэгдэл ба лимитэд багтана |
| `Amount` | `Zero` | `0` |
| `Amount` | `OverBalance` | Хөрвүүлсний дараа үлдэгдлээс хэтэрнэ, лимитэд багтана |
| `Amount` | `OverLimit` | Хөрвүүлсний дараа лимитээс хэтэрнэ, үлдэгдэлд багтана |
| `Currency` | `Same` | Дансны валюттай ижил |
| `Currency` | `Different` | Дансны валютаас өөр |

### A1.1 Далд орчны өгөгдөл

Шилжүүлгийн үр дүн нь зөвхөн API-ийн оролтоос бус, дансны төлөв болон санхүүгийн мэдээллээс хамаарна.

| Орчны өгөгдөл | Зориулалт |
|---|---|
| Дансны үлдэгдэл | Шилжүүлэх дүн хүрэлцэх эсэх |
| Өдрийн нийт лимит | Өдрийн зөвшөөрөгдсөн хэмжээ |
| Өнөөдөр ашигласан лимит | Үлдсэн лимитийг тооцох |
| Дансны валют | Хөрвүүлэлт шаардлагатай эсэх |
| Валютын ханш | Хөрвүүлсэн дүнг тооцох |
| Дансны оршин байх болон frozen төлөв | From, To ангиллыг тодорхойлох |

**Тооцоолол:**

Үлдсэн лимит = Өдрийн нийт лимит - Өнөөдөр ашигласан дүн

Хөрвүүлсэн дүн = Amount × Валютын хөрвүүлэх ханш

Эдгээр орчны өгөгдлийг PICT-ийн бие даасан параметр болгохгүй. Харин Amount ангиллын тестийн setup-д ашиглана.

### A1.2 Валют ба дүнгийн төлөөлөх утгууд

Тестийн орчны валютыг MNT гэж сонгосон.

- Дансны валют: MNT
- Same валют: MNT
- Different валют: USD
- Тестийн ханш: 1 USD = 100 MNT

Энэ ханш нь зөвхөн лабораторийн тестийн зориулалттай бөгөөд бодит зах зээлийн ханш биш.

| Amount анги | Үлдэгдэл MNT | Үлдсэн лимит MNT | Same: MNT | Different: USD | Хөрвүүлсэн дүн MNT |
|---|---:|---:|---:|---:|---:|
| Normal | 1000 | 800 | 100 | 1 | 100 |
| Zero | 1000 | 800 | 0 | 0 | 0 |
| OverBalance | 1000 | 2000 | 1100 | 11 | 1100 |
| OverLimit | 2000 | 800 | 900 | 9 | 900 |

### A1.3 Ангиллын үндэслэл

From параметрт дансны оршин байх болон царцаагдсан төлөвийг шалгана. To параметрт хүлээн авагч данс байгаа эсэх, хоёр данс ижил эсэхийг шалгана.

Amount параметрт зөв дүн, тэг утга, үлдэгдэл хэтэрсэн болон өдрийн лимит хэтэрсэн нөхцөлүүдийг ялгасан.

OverBalance болон OverLimit ангиллыг тусгаарлахын тулд тестийн орчны үлдэгдэл болон лимитийг өөрөөр бэлтгэнэ.

Currency параметрт ижил болон өөр валюттай шилжүүлгийг хамруулсан.

Ингэснээр шилжүүлгийн үндсэн зөв болон алдаатай нөхцөлүүдийг төлөөлөх утгуудаар тодорхойлсон.

## Даалгавар A2 — Хязгаарлалтууд:

### A2.1 Ангиллуудын тэмдэглэгээ

Category-Partition аргаар тодорхойлсон сонголтуудад ERROR, SINGLE болон Property тэмдэглэгээг оноосон.

| Параметр | Утга | Тэмдэглэгээ | Үндэслэл |
|---|---|---|---|
| From | Valid | Property: fromExists, fromUsable | Байгаа, ашиглах боломжтой данс |
| From | Frozen | ERROR | Царцаагдсан дансны алдааг тусгаарлана |
| From | Missing | ERROR | Шилжүүлэгч данс байхгүй |
| To | Valid | Property: toExists, differentAccount | Хүлээн авагч данс байгаа, өөр данс |
| To | Missing | ERROR | Хүлээн авагч данс байхгүй |
| To | SameAsFrom | ERROR, IF fromExists | Хоёр данс ижил |
| Amount | Normal | Property: positive, withinBalance, withinLimit | Дүн бүх нөхцөлийг хангана |
| Amount | Zero | SINGLE | Тэг дүнг нэг тусгай кейсээр шалгана |
| Amount | OverBalance | ERROR | Дүн үлдэгдлээс хэтэрсэн |
| Amount | OverLimit | ERROR | Дүн өдрийн лимитээс хэтэрсэн |
| Currency | Same | Ердийн утга | Валютын хөрвүүлэлтгүй |
| Currency | Different | Ердийн утга | Валютын хөрвүүлэлттэй |

### A2.2 Тэмдэглэгээний тайлбар

**ERROR:**
Алдаатай нөхцөлийг тусгаарлан тестлэхэд ашиглана. Бусад параметрүүдийг зөв утгатай байлгаснаар тухайн алдааны хүлээгдэх үр дүнг тодорхой шалгах боломжтой.

**SINGLE:**
Тухайн сонголтыг нэг тусгай test frame-д оруулах бодлого юм. Amount.Zero утгыг SINGLE гэж сонгосон боловч энэ нь амжилттай шилжүүлэг гэсэн үг биш. Хүлээгдэх үр дүн нь ERROR_BAD_AMOUNT байна.

**Property:**
Сонгосон утгын хангаж буй шинж чанарыг илэрхийлнэ. Жишээлбэл From.Valid нь fromExists болон fromUsable шинж чанарыг хангана.

**IF:**
Тестийн сонголтуудын хоорондын хамаарал болон хязгаарлалтыг тодорхойлно.

### A2.3 IF хязгаарлалтууд

Дараах дөрвөн хязгаарлалтыг сонгосон.

1. From = Missing бол To != SameAsFrom.
2. From = Missing бол Amount = Normal.
3. To = Missing бол Amount = Normal.
4. Amount = Zero бол Currency = Same.

**Хязгаарлалтын үндэслэл:**

- IF1: SameAsFrom сонголтыг байгаа шилжүүлэгч данстай нөхцөлд шалгана.
- IF2: Шилжүүлэгч данс байхгүй үед дүнгийн давхар алдааг үндсэн загварт оруулахгүй.
- IF3: Хүлээн авагч данс байхгүй үед дүнгийн давхар алдааг үндсэн загварт оруулахгүй.
- IF4: Zero утгыг Same валюттай нэг тусгай SINGLE кейсээр шалгана.

IF2, IF3, IF4 нь бодит системийн хувьд боломжгүй нөхцөлүүд биш. Харин тестийн тоог удирдах, алдааг тусгаарлах зорилготой дизайны шийдвэр юм.

Хязгаарлалтаас хасагдсан зарим давхар алдаатай нөхцөлийг A3 хэсэгт тусгай тестээр шалгана.

### A2.4 Бүрэн олонлогийн тооцоо

Дөрвөн параметрийн утгын тоо:

| Параметр | Утгын тоо |
|---|---:|
| From | 3 |
| To | 3 |
| Amount | 4 |
| Currency | 2 |

Бүрэн олонлог:

N = 3 × 3 × 4 × 2 = 72

Иймээс хязгаарлалтгүй үед нийт 72 боломжит хослол байна.

### A2.5 IF хязгаарлалтын дараах тооцоо

Дөрвөн IF хязгаарлалтыг хэрэглэсний дараах боломжит хослолууд:

| From төлөв | Зөвшөөрөгдөх хослол |
|---|---:|
| Valid | 16 |
| Frozen | 16 |
| Missing | 4 |
| Нийт | 36 |

Тооцоолол:

16 + 16 + 4 = 36

Ингэснээр 72 боломжит хослолыг 36 болгон бууруулсан.

### A2.6 ERROR болон SINGLE сонголтын дараах тооцоо

Үндсэн тестийн frame-үүдийг дараах байдлаар сонгосон.

| Ангилал | Тооцоо | Frame |
|---|---|---:|
| Алдаагүй нөхцөл | 2 валют | 2 |
| ERROR утгууд | 6 ERROR × 2 валют | 12 |
| Zero SINGLE | 1 тусгай кейс | 1 |
| Нийт | 2 + 12 + 1 | 15 |

M = 2 + (6 × 2) + 1 = 15

Энэ нь гараар сонгосон үндсэн frame-ийн төлөвлөсөн тоо юм. PICT-ийн автоматаар үүсгэх мөрийн тоо биш.

### A2.7 N → M бууралтын үр дүн

Бүрэн олонлог: 72

IF хязгаарлалтын дараа: 36

ERROR/SINGLE сонголтын дараах үндсэн frame: 15

Бууралтын хувь:

(72 - 15) / 72 × 100 = 79.17%

Ингэснээр бүх боломжит хослолыг шалгахын оронд алдааг тусгаарласан, төлөөлөх тестийн frame-үүдийг сонгох боломжтой болсон.

A3 хэсэгт нэмэх boundary болон давхар алдааны кейсүүдийг энэхүү 15 үндсэн frame-ээс тусад нь тооцно.
